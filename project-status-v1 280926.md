# Отчет по проекту: Fishing Tournament Portal (MVP)
**Статус:** Успешно развернута база проекта, подключено офлайн-хранилище и реализовано ядро калькулятора.
**Текущая дата:** 24 сентября 2026 г.

---

## 1. Что УЖЕ сделано к настоящему моменту

### Архитектура и Окружение
* **Развернута структура монорепозитория (npm workspaces):** Созданы изолированные зоны для фронтенда (`apps/front`), бэкенда (`apps/back`) и общего кода (`packages/shared`).
* **Настроен TypeScript:** Общие конфигурации компилятора увязаны между всеми пакетами.
* **Подготовлен файл контекста ИИ:** В корне создан `ARCHITECTURE.md`, фиксирующий для Cursor правила PAL Trout, концепцию Event Sourcing и принципы экономии токенов.

### Фронтенд (Client-Side)
* **Инициализирован стек React + Vite + TS:** Окружение настроено и запущено на Node.js v20.
* **Развернут UX/UI Экрана Спортсмена:** Сверстан адаптивный мобильный интерфейс с крупными контрастными элементами управления (кнопки «ПЛЮС»/«МИНУС» для поимок своего и чужого улова, таймер периода).
* **Подключено Offline-First хранилище:** Интегрирована библиотека `Dexie.js`. В браузере успешно создается база данных `FishingTournamentPortal` и таблица `events`. Все клики по фиксации периодов гарантированно записываются на диск устройства в формате неизменяемого лога событий (`TournamentEvent`), работая полностью без сети.

### Ядро расчетов (Shared Engine)
* **Реализованы типы данных (`types.ts`):** Спроектированы строгие интерфейсы для событий (`PARTICIPANT_REGISTERED`, `CATCH_RECORDED`, `PERIOD_COMPLETED` и т.д.), сущностей участников и матчей.
* **Написан калькулятор (`calculator.ts`):** Реализована чистая математика турниров по официальному регламенту PAL Trout:
  * Начисление очков по схеме **4 / 2 / 1 / 0** (включая учет 0 очков при сухих играх и счете 0:0, а также 1 очко за поражение с рыбой).
  * Алгоритм генерации таблицы лидеров (`generateLeaderboard`) с сортировкой по сумме очков, а при равенстве — по общему количеству рыбы.
  * Механика «быстрых замен» без разрушения сгенерированной матрицы переходов (замена только метаданных имени по неизменному ID).
  * Логика сравнения одиноких спортсменов в нечетных турах через механизм событий (`LONE_COMPARED`).

## 2. Что ПРЕДСТОИТ сделать (План разработки)

### Ближайшие шаги (Фронтенд для тестов с товарищем)
1. **Интеграция Калькулятора в UI:** Связать Zustand-стор и IndexedDB с shared-движком расчетов, чтобы лог событий автоматически конвертировался в актуальное состояние турнира.
2. **Экран турнирной таблицы (Leaderboard):** Сверстать вкладку лидерборда для организатора со спортивной сортировкой, выделением проходных мест в плей-офф (топ-4 / топ-8) и интерфейсом ручной фиксации результатов одиночек.
3. **Загрузка/Парсинг матрицы жеребьевки:** Создать интерфейс для загрузки или ввода готовой карты переходов/дуэлей, чтобы приложение знало расписание секторов на все 10 периодов вперед.

### Среднесрочные задачи (Локальная синхронизация и P2P)
1. **Модуль офлайн-синхронизации (QR / P2P):** Разработать генератор компактных динамических QR-кодов для судей на секторах и сканер для телефона организатора, чтобы собирать логи событий без интернета.
2. **Превращение в PWA:** Доработать Service Worker, чтобы приложение гарантированно открывалось и работало "из кэша" посреди глухого леса без сети.

### Дальнейший масштаб (Коммерциализация и Бэкенд)
1. **Реализация API сервера (`apps/back`):** Написать Express-контроллеры для приема накопленных пакетов событий и валидации их через тот же shared-калькулятор.
2. **База данных PostgreSQL:** Спроектировать схему хранения логов турниров, профилей спортсменов и сквозных рейтингов.
3. **Модуль расширения рулсетов:** Добавление плагинов (стратегий калькулятора) под карпфишинг, фидер и лодочный спиннинг для масштабирования платформы на весь рыболовный спорт.
