# Проект: Fishing Tournament Portal (Движок офлайн-расчетов)

## 1. Архитектура проекта
- Это монорепозиторий (npm workspaces).
- `packages/shared` — содержит общие типы и чистые функции расчетов (Pure Functions) на TypeScript. Этот код импортируется как во фронтенд, так и в бэкенд.
- `apps/front` — Offline-First SPA/PWA на React + Vite + Zustand + Dexie.js (IndexedDB).
- `apps/back` — Node.js + Express + PostgreSQL.
- Подход к данным: Event Sourcing. Любое действие (поимка рыбы, замена игрока) — это неизменяемое событие (`TournamentEvent`), записываемое в IndexedDB.

## 2. Бизнес-логика (Регламент PAL Trout)
- Сетка дуэлей (1 на 1). Меньший номер всегда заходит в сектор СЛЕВА. Смена сторон в середине периода — только по требованию одного из спортсменов.
- Начисление очков за дуэль:
  * Победа = 4 очка.
  * Ничья с рыбой (у обоих > 0) = 2 очка.
  * Поражение с рыбой (у проигравшего > 0) = 1 очко.
  * Ноль поимок (включая поражение всухую 0:X или ничью 0:0) = 0 очков.
- Генератор сетки отсутствует. Система парсит и рассчитывает готовую загруженную матрицу жеребьевки/переходов.
- Нечетное количество игроков: Результат одиночки сравнивается с результатом соседа по сектору (алгоритм калькулятора должен принимать ID соседа для сравнения).
